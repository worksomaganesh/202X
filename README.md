- **November 2026:** Build core programming foundations, research eligible roles, and start documenting progress.

## 🛠️ How I Will Learn

1. Learn a concept and practise it.
2. Build something that uses it.
3. Document what worked, what failed, and what I learned.
4. Publish meaningful progress and improve through feedback.
5. Apply for opportunities before I feel completely ready.

## 📈 Progress Tracking

Every weekly review will capture:

- What I planned to do.
- What I actually completed.
- What I built or tested.
- Problems and blockers I encountered.
- Hours spent and applications/assessments completed.
- What I will do differently next week.

## ✅ Ground Rules

- Prioritise understanding over collecting certificates.
- Build working projects instead of copying tutorials without understanding them.
- Keep project instructions, dependencies, limitations and results documented.
- Apply to opportunities that match my actual eligibility.
- Be honest about skills, project contributions and achievements.
- Never commit passwords, API keys, access tokens or other secrets.
- Cut low-priority topics before sacrificing core projects or consistent applications.
- Never pay a recruiter or platform to secure an internship or interview.

## 🧭 The Principle

**Learn → Build → Document → Apply → Improve → Repeat**

This repository will document the process, including setbacks and unfinished experiments — not just the highlights.

The objective is not to look skilled on paper. It is to become skilled enough to demonstrate real work and earn my first internship.
