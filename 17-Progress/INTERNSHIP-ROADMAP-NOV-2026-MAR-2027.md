# Internship Roadmap — November 2026 to March 2027

**Mission:** secure one genuine first-year internship by **31 March 2027**.  
**Start:** 1 November 2026, after first-semester mid-examinations.  
**Study capacity:** ~20–22 hours/week (weekday 2 hours/day, weekend 5–6 hours/day).  
**Stretch readiness checkpoint:** 18–24 January. **Safer portfolio-ready target:** 1–7 February. February–March are not “wait until then” months: applications run in parallel from the early stages.

## Strategy

1. Learn the core slice needed for several adjacent roles, not every technology in the AIML universe.
2. Build projects while learning; don't wait for every skill to be finished before applying.
3. Start tracking and checking eligible openings in November; begin applications as soon as the first project/resume is credible, ideally late November/December.
4. Treat first-year eligibility as role-specific. Read the exact posting's year-of-study, location, work authorization, schedule, duration and stipend details.
5. Apply to legitimate Python/automation, data, AI application, QA/testing and selected SWE roles. ML internships are a stretch category; big-tech roles are worthwhile only when eligibility fits.
6. Keep March as the final buffer for setbacks, interviews and follow-ups. An internship is not guaranteed, so review response data weekly and change strategy.

## Two-track operating model

- **Track A — AI/ML specialization:** Python, SQL, statistics, NumPy/pandas, EDA, model evaluation, ML, later deep learning/data engineering/AI systems, and Kaggle competitions.
- **Track B — general engineering:** Git, debugging, DSA, software design, testing, Linux, databases, APIs, communication and interviews.
- Python, SQL, Git, debugging and testing are shared foundations. Keep DSA in its existing weekly parallel slot.
- Use AI agents as bounded assistants for explanation, candidate code, debugging and review. The learner still runs code, checks evidence, understands the result and owns the final decision.

## Project sequence (reuse the existing folders)

### Project 00 — GitHub Foundation
Purpose: show you can set up a clean repo, README, environment, issues/checklist, useful commits and basic tests. This is a foundation exercise, not a flagship portfolio project.

### Project 01 — Smart File Log Analyzer
Skills: Python, file handling, exceptions, pathlib, CSV/JSON, logging, tests.  
MVP: read sample logs, count event levels/errors, summarise timestamps/categories, handle malformed lines and export a report. Do not include real private logs or secrets.

### Project 02 — E-commerce Business Analytics
Skills: SQL, pandas, data cleaning, EDA, charts, business reasoning.  
MVP: use a public/synthetic dataset, document schema, answer 5–8 business questions, show queries/charts and state limitations. Never fabricate business impact.

### Project 03 — ML Prediction Project
Skills: pandas, scikit-learn, train/test split, baseline, appropriate metrics, error analysis.  
MVP: a modest public dataset, documented target/features, no leakage, compare baseline with one or two models, report limitations, add a reproducible run command.

### Project 04 — Job Description Analyzer
Skills: Python, LLM API (or a deterministic fallback), structured output, basic API/UI, validation, testing.  
MVP: paste a job description, extract skills and requirements, produce a skill-gap checklist, and link claims to source text where possible. Test malformed input and unsupported claims; label AI-generated output. Never promise that an AI match score predicts hiring success.

## Application strategy

- **November:** learn role names, eligibility rules, scam signals and set up the tracker. Save promising openings and deadlines.
- **Late November–December:** start applying when Project 1 and a truthful resume are presentable; do not wait for all four projects.
- **January:** apply consistently while polishing projects. Search for openings with first-year eligibility explicitly stated or no incompatible year restriction.
- **February:** widen across relevant roles and verified startups; improve application quality based on response patterns.
- **March:** final focused push, assessments, interviews and follow-ups. Continue to apply until an offer is confirmed.

Track weekly: relevant openings found, eligible applications submitted, assessments, replies, interviews, rejections, follow-ups and lessons. Do not measure success only by raw application count.

## Obstacle protocol

- **Lost 1–3 days:** resume at the next unfinished task; do not restart the entire course.
- **Lost one week:** cut Category 4 topics and project polish before cutting core Python, project completion or applications.
- **ML takes too long:** ship a small, correctly evaluated baseline; target Python/data/automation/AI-app roles too.
- **LLM/RAG gets stuck:** use a smaller API-based demo or deterministic fallback; test and document limitations.
- **No replies after ~20 well-matched applications:** inspect eligibility, resume relevance, proof links and role targeting; ask for feedback and revise rather than spamming.
- **Only unpaid or suspicious offers:** verify company identity, supervisor, deliverables, terms, fees and data handling. Never pay to secure an internship or share secrets.
- **Exam/college workload spikes:** keep a minimum viable week (small coding session, one project task, tracker review); move optional topics to buffer weeks.

## Definition of success

Primary goal: a genuine internship offer/selection by 31 March 2027, subject to actual openings and eligibility. A high-quality portfolio is a controllable intermediate outcome, not a guarantee of selection. Keep every claim in the repository accurate and dated.
